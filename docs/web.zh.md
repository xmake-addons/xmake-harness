# Web 界面

[English](web.md) | 中文

```bash
$ xmake ai --web
```

它在本地回环上起一个小的 http 服务，打印一个带 token 的 url，并自动用默认浏览器打开。
后面是同一个 harness：同样的工具、同样的技能、同样的权限模式、同样的会话文件。
它是第二个前端，不是第二个 agent。

它打开的是**当前工程的上一次会话**，而不是空会话 —— 浏览器是一个开着不关的窗口，
刷新、崩溃、笔记本睡醒都算「重启」，对话、改动列表和你做过的决定都还在。
`--web --new` 才开新的，左上角那个 ＋ 也是。

```
  web ui  http://127.0.0.1:9736/?token=e07091070…
  project /path/to/your/project
```

| 选项          | 作用                                              |
|---------------|---------------------------------------------------|
| `--web`       | 启动 web 界面，而不是终端界面                      |
| `--port=N`    | 监听端口，默认 `9736`（被占用就往后取第一个空闲的） |
| `--nobrowser` | 不打开浏览器，只打印 url                           |
| `--cwd=DIR`   | 要打开的工程目录，默认是当前目录                    |
| `--mode=M`    | 启动时的权限模式，默认 `acceptedits`               |

## 界面里有什么

- **Chat** —— 对话本身。回答是流式出来的；工具一开始执行就先出一张卡片
  （构建慢不等于界面卡住），执行完的卡片可以展开；推理模型的思考过程收在
  单独的折叠块里。改文件会直接显示 diff，一轮结束后再汇总列出这一轮改过的所有文件。
- **Changes** —— 这次对话改过的文件：左边是列表，右边是选中文件的 diff，带语法高亮，
  每个文件上有一个勾和一个叉：保留改动，或者还原。
- **History** —— 当前工程的历史会话。点开就是继续那次对话，所有打开的标签页会一起切过去。
- **Settings** —— 工程目录、主题、大模型服务商、模型和 api key，按分区排列。

主题默认跟随系统，也可以固定成白天或者夜间。主题是页面自己的事情，不会发给 harness。

手机上导航栏会移到底部（拇指能够到的地方），Changes 页也从左右两栏变成上下一栏。

## 斜杠命令

终端里有的这里都有：在输入框里打 `/` 就会列出来，边打边过滤，Tab 或回车选中。

它们就是**同一批**命令 —— `/compact`、`/context`、`/cost`、`/model`、
`/permissions`、`/rewind`、`/skills`、`/xmake`，以及插件加的那些 ——
走的是适配层而不是重写一遍，所以一个命令只写一次，两边都能用。
`/xmake build` 在这里同样能跑；这里没有终端可以交出去，所以输出会被捕获，
以卡片的形式出现在对话里。

命令要问你问题时，用的也是对话里那张卡片，和工具确认一样。

## 附带文件

输入框里打 `@` 会补全工程里的文件 —— 有 git 仓库时走 `git ls-files`，
所以被 ignore 的东西不会来打扰你 —— 发送时文件内容会附在消息后面，和终端里一样。
两个前端调用的是同一份展开逻辑，所以 `@src/main.c` 只有一种含义。

## Changes 页

它列的是**这次对话**改过的文件，只有这些。

不是 `git status`：工作区里本来就有什么它都会显示 —— 早上没写完的东西、build 目录、
忘了删的临时文件 —— 这些都不是「它改了什么」这个问题的答案。

一个文件的 diff，是它在本次对话第一次被改动之前的内容，对比它现在的内容 ——
中间被写过多少次都一样。那个「之前」正是每次写入为 `/rewind` 保留的副本，
所以是同一套机制，不是两套。

**命令**写出来的文件也算。`xmake create -t console hello` 一口气写十一个文件，
而且什么都不告诉我们，所以每条命令都被前后夹住：跑之前工程是什么样、跑完是什么样、差在哪。
这套办法给不了的是「被命令覆盖掉的文件之前是什么」—— 没人事先知道它要写哪些文件 ——
所以那种行会标 `by a command`，既没有 diff 也没有还原按钮，而不是假装有。
在工程目录之外写文件的命令，工程本身是看不见的。

每个文件有两个答案，都是一次点击 —— 一个勾一个叉，列表行上有，diff 右上角也有：

- **勾 —— keep** —— 这个改动没问题。它不写任何文件，改变的只是这个列表 ——
  这是一个「还没做决定」的列表。导航栏上的角标数的就是还没决定的那些。
- **叉 —— revert** —— 把文件恢复成本次对话动它之前的样子。agent 新建的文件则是删掉。
  那一行会留下并标记为 *reverted* —— 一个消失了的决定，事后谁也查不到。

列表头上是同样两个按钮的「全部」版本：**全部保留**处理所有未决定的；
**全部回退**要点两次 —— 它会丢掉工作，不该让一次误点就做到。

决定写在会话里，不是存在服务端内存里：重启 harness、换个标签页，
都不会再问你同一个改动。如果 agent 在你做出决定**之后**又改了这个文件，
那就是一个新的改动，列表会重新问 —— 这正是它存在的意义。

列表会跟着 agent 走：开着这一页看它干活，每个文件写完就出现在列表里，
而你正在看的那个 diff 会留在屏幕上。

一轮结束时对话里那份文件列表就是同一份：点其中一个就跳到这里，带着 diff 和这两个按钮。

## 不依赖任何第三方

没有框架，没有打包器，没有构建步骤。页面就是普通的 html、css 和 es module，
直接从 `src/modules/harness/web/assets` 提供：改一个文件、刷新页面，就是全部的开发流程。

markdown 由 harness 渲染 —— 和终端界面用的是同一个解析器 —— 以 html 的形式过网络，
所以浏览器里不存在第二个渲染器，也就不会和第一个渲染出不一样的结果。

事件走 [server-sent events](https://developer.mozilla.org/docs/Web/API/Server-sent_events)，
浏览器原生支持，断线会自己重连。重连的流上不会重放任何事件：
页面回来之后重新拉一次状态即可，这样历史只有一份，不需要再为重连维护第二份。

## 权限确认

权限模式和终端里完全一致，判断规则也是同一套：`ls`、`git status`、`xmake build`
直接执行；难以撤销的、伸到工程外面的、或者我们根本读不懂的命令，才会先问一句。

问题出现在**对话流里面**，和这一轮其它内容排在一起，而不是盖在页面上的弹框。
改文件时会带上 diff，选项和终端一致（包括「以后不再问」），
回答之后卡片留在原地，并显示你当时选了什么。

这一轮会停在那里等答案，等待本身不消耗任何东西；问题会推送到所有打开的标签页，
在其中一个回答，其它页面上的卡片一起结束。开着问题时按停止或 Esc，等于回答「不」。

输入框左下角那个就是权限模式，点一下按 shift+tab 的顺序循环切换。

## 一直开着的成本

只有一个 socket。全程没有任何轮询：挂起的事件流就是一个挂起的协程，
标签页关掉了，下一次往它推东西的时候自然就发现了。

## 安全

服务只绑定 `127.0.0.1`，并且要求 token。token 每次运行重新生成，进程结束就没了。
token 在 url 里，这个 url 不要分享出去：机器上任何能开 socket 的东西都能访问回环地址，
而这是一个能改文件、能执行命令的服务。

页面自身的文件 —— css、js、logo —— 不需要 token，因为 es module 的 `import`
带不了这个参数。它们对所有人都一样，本身不含任何信息。

api key 是设置页唯一不会回读的东西。页面只显示「有没有配」，允许你替换它；
key 本身留在 `~/.xmake/harness/config.json` 里，不会过网络。

## 多个标签页，一个对话

每个标签页看到的是同一个对话、同样的事件。中途打开的标签页从会话文件里重建界面，
那也正是终端界面读的同一个文件 —— 所以在浏览器里开始的对话，可以用
`xmake ai --resume` 在终端里继续，反过来也一样。

## 运行过程中

输入框下面那行会用文字说明它在干什么 —— thinking、reasoning、writing，
或者正在跑的工具名 —— 旁边就是停止按钮。

agent 自己维护 todo 计划时，输入框上方只占**一行**：完成进度加当前这一条。
整个列表折叠着，点一下展开 —— 一个把对话挤出屏幕的计划面板，
回答「还剩多少」的次数远不如它挡住「它说了什么」的次数多。

状态栏显示上下文窗口用了多少，用的和自动压缩同一套度量 —— 你看到的就是 harness
据以行动的那个数。超过 70% 变黄，超过 85% 变红，两种情况的解法都是 `/compact`。

## 一些细节

- 鼠标移到回答上会出现 **copy**，回答里的每个代码块也各有一个
- 回答还在流式输出时往上翻，视图会停止跟随，并出现一个跳回最新的按钮
- **History** 里可以删除会话，需要点两次：第二次会说清楚它要干什么
- **Esc** 停止当前轮；有问题卡片开着时，等于回答「不」
- 出错的那一轮会带一个 **retry** 按钮 —— 一般都是服务商抽风，
  这时候需要的就是把同一句话再发一次
- **Settings** 里有 *run /doctor* 按钮：设置页自己回答不了的那个问题是「这些配置到底能不能用」
- 几千行的 diff 先画 600 行，剩下的一键展开，打开它不会卡一下
- 鼠标移到自己发过的消息上会出现 **edit**，把它放回输入框 ——
  看完回答之后最常做的事就是换个说法再问一遍
- 标签页在后台时某一轮跑完了，标题前面会加一个圆点，你一看它就消失；
  这件事不需要申请任何权限
- 所有能接收键盘的控件都有 focus 环，但只在用键盘走到它时出现，鼠标点击不会
- 标签页标题带工程名 —— 同时开两个是常态，两个都叫 "xmake ai" 等于没说
- harness 断开时（重启、停掉）页面会明确提示，而不是安静地什么都不显示

## 出问题的时候

打开浏览器的控制台。页面把画不出来的东西报在那里，并且继续运行，而不是整页白掉。

如果页面一直打不开，看一眼终端里打印的 url：端口被占用时 harness 会顺延到下一个空闲端口，
终端里打印的那个才是对的。
